\section{Threats to Validity}
\label{sec:threats}

\textbf{Internal and construct validity.} Our minimal-fix oracle can accept compensating fixes and never searches
alternatives for reachable labels, so the repaired labels are still noisy; we drop fixes written onto blank lines and
report every result on the original labels as well. Because the oracle needs a failing test to reach the fixed line, the
repaired labels favor coverage-based methods; we therefore state the main comparison on reached faults of the original
labels and give the all-label numbers next to it. The oracle's proposer (GPT-6 luna, then Claude Sonnet~5.5) is also an
evaluated model; the tests, not the proposer, decide, but the proposer limits which locations can be confirmed.
Line-level Acc@1 depends on whether a guard or the guarded statement is labeled; we report tolerant variants. The
coverage prompt is ours, fixed before seeing test results, and adds test outcomes as well as coverage, so it does not
isolate coverage.

\textbf{External validity.} Real bugs come from one project (31 youtube-dl bugs) and the target function is chosen from
the developer fix, so function-level localization is not evaluated. RQ2, the decomposition and the renaming study use one
model; the model-family subset has no CIs. Models run at provider-default reasoning, so the family comparison is ``at
default'' rather than at equal effort; the main model is newer than those in the original paper, and our re-execution
with the paper's model fell short of the published logs. Renaming changes identifiers and comments but not structure, so
memorization of templates is not fully excluded.
